# 《旅册》原型设计方向

一期 demo：输入目的地（长白山 / 延吉）→ 生成一本"自己的旅行书"→ 行前阅读知识章节 → 行中完成探索任务、拍照打卡 → 行后成册回顾。

## 品牌宣发叙事（对外）

这部分用于小红书、短视频、朋友圈、落地页或创始人介绍，回答“我们为什么要做这件事”。它不是产品首页的逐字文案，也不应原样塞进 App。

### 一句话主张

**带着疑问出门，揣着故事回来。**

### 长版宣发文案

> 现在的旅行，越来越像一场体力活。
>
> 查不完的避坑指南，做不完的完美攻略。几点起、去哪拍、吃哪家网红店——我们把异国他乡的街头，过成了精确到分钟的 KPI。
>
> 人是到了，照片也有了，但好像只是换了个地方刷手机。直到很久以后，看到某张照片或者偶然读到一本书，才突然拍大腿：原来当年那个路口，藏着这么有意思的故事？可那时候，你已经不在现场了。
>
> 我们不想再给你一份密密麻麻的打卡清单。
>
> 这次，我们只想帮你重新带上好奇心。去看看眼前这座山、这条街、这顿饭背后真正动人的地方。
>
> **带着疑问出门，揣着故事回来。**

### 短版／社媒传播文案

> 攻略越来越厚，旅行怎么越来越像完成任务？
>
> 每一篇攻略都在教你“去哪儿”，却很少有人告诉你：这块砖、这碗面、这座城，凭什么值得你停下来看一眼？
>
> 别再机械式打卡了。
>
> **这次，我们帮你真正看懂一个地方。**

### 宣发叙事边界

- 不贬低攻略：攻略解决的是决策成本；《旅册》解决的是进入一个地方前的理解与在场感。
- 不把用户当学生：不说“学习”“科普”“提升”，以好奇、发现、现场细节和个人感受表达。
- 旅行书是结果和回访入口；核心价值在行前带着问题出发、行中观察记录、行后重新理解。

## 产品内容（产品内）

产品内不复述“攻略让旅行没意思”的长篇观点，而要让用户迅速知道此刻能得到什么、下一步做什么。

- **入口任务**：自由输入 1–3 个目的地，生成一册属于这趟旅行的旅行书。
- **生成承诺**：得到与这次选择相匹配的书名、副标题、书脊与封面；书内主动呈现每个目的地的多层特色，并围绕行程组织阅读与现场探索。
- **书架任务**：历史旅册以“书脊 → 抽出展示封面 → 旅行介绍 → 开始翻阅”的链路陈列和进入。
- **行中任务**：不是照着清单赶路，而是在恰当时刻收到一个具体的观察线索、问题或记录邀请。

产品内的首页标题应短、具体、可行动；例如“这次想去哪里？”或“为下一次旅行，做一本自己的书。”不要直接使用长版宣发文案。

### 首页书架实施说明（2026-09）

- 创建表单仍是一张纸；历史书架移至纸卡之后，成为用户向下继续探索的独立段落，不把首页重做成新的信息架构。
- 默认只呈现可读书脊。点按某一本，先把它沿横向轨道滚动到中央，停稳后再让整本闭合的书转向读者：正封面从侧面转出，书脊面同步转为左侧窄边，两面始终保持实体书的空间关系。层板下方展示旅册信息，用户再次按“翻开这本书”才进入阅读。
- 书架是纯 HTML/CSS 的固定正面视角，不加载 Three.js 或 WebGL。所有书在单层轨道中横向排列，支持触控板、鼠标与手机手势左右滚动。
- 每本书的厚薄和高度由该书自身稳定派生；同一本书的书脊、封面共享高度、底边抬升和透视轴，禁止使用独立固定高度。只有选中书使用受控的整体转向，其他书脊保持正面直立。切换书籍时先把当前书转回书脊面，再移动下一本。
- 轨道首尾保留居中缓冲区，第一本与最后一本也能精确滚到中央；“上一册 / 下一册”按真实索引切换并再次居中。
- 提供“书架 / 列表”双视图。列表按书名、地点和日期展示，并支持搜索书名或地点；两种视图共享选中状态和下方详情。
- 历史书优先使用已生成的整书封面；旧条目缺少封面图时，客户端以书名、日期和书脊配色即时合成可辨识封面，不能留空白封面。
- 长按本地书仍可移除。旅行介绍页是书架与正文之间的下一阶段工作，本次首页先完成选择态与明确的阅读入口。
- 开发验收可在首页追加 `?shelfPreview=1`，补足 16 本排布样书；样书不进入历史数据，也不能打开正文。

### 信息架构决策：书架与新建入口（待实施）

- **有书的回访用户默认进入“我的书架”**，不再在书架上方堆叠完整的输入表单。书架是回访首页，不是首页下半截的一个区块。
- 右上角保留唯一主动作 `制作一本旅行书`；点按后进入独立的“新建旅册”屏，顶部只保留 `返回书架`。提交成功后进入工坊，完成后回到刚生成并选中的书。
- **首次用户没有书架可逛**，首页直接是新建旅册屏；不显示一个空的大书架。可保留“先看看一本做好的”作为次级入口。
- 产品内不用“生成一本书”作为到处重复的按钮文案：用户主动动作统一叫 `制作一本旅行书`，工坊状态才使用 `正在生成内容` / `装订中` 等系统描述。
- 不采用底部“书架 / 新建”双主导航；新建是低频且有明确开始/完成边界的动作，放在全局主按钮中即可。

### 首页品牌与首屏文案（待实施）

- `旅册` 是产品/IP 名，必须作为每种首页状态都可见的固定品牌锚点；“我的书架”只能是回访页的内容标题，不能取代 `旅册`。
- 保留首屏现有的三段排版结构：`A Book Made For Your Trip` 小标 → 一句主张 → 一段解释。但不使用小红书长文中的“带着疑问出门，揣着故事回来”作为首页主张；它属于对外叙事，而非一眼说明产品价值的产品文案。
- 推荐首页文案：
  - 小标：`A Book Made For Your Trip`
  - 主张：`攻略告诉你去哪儿，旅册让你知道为什么值得去。`
  - 解释：`你可以照着攻略抵达一个地方，却未必真正走进它。旅册会为你搜集一个地方的故事、文化和日常，再做成一本属于这趟旅行的书。`
- 禁用“攻略解决的是走马观花”这类逻辑不准确的对立；也不承诺“实体旅行书”，一期交付是可翻阅的数字旅行书。
- 三步说明不使用“工坊现场考据”“沉淀叙事骨架”等拟人化 AI 行话。改为：`写下想去的地方` → `我们为你搜集资料` → `得到一本专属于这趟旅行的书`。标题可用自然的 `一本旅册，怎么做出来？`，不显示“新手引导”徽标。

### 首次、回访与教程的显示规则（已确认）

- 首次用户看到扉页、三步图文教程和新建表单；首屏正文固定为三行：`你可以照着攻略抵达一个地方，` / `却未必真正走进它。旅册会为你搜集一个地方` / `的故事、文化和日常，再做成一本独属于你这趟旅行的书。`
- 教程只在首次态常驻。回访用户默认进入书架；从书架新建时进入独立新建页，教程仅作为按需查看的说明，不占页面。
- 首次页底部展示“我的书架”的单册预览，样板书是可翻阅的书架物件，不使用孤立的 `Sample` 推荐卡。完成第一本以后，这个位置由真实历史书架取代。
- 四行产品介绍和“如何生成”教学都不是常驻首页内容：首次打开 App 时作为一次性扉页内的两步出现。第 1 步为英文小标、`旅册` 与四行固定排版图片；第 2 步为三张“如何做出来”的图文卡，最后进入“开始做一本旅行书”。确认后不再自动展示。首页与新建页不常驻教程；后续在“关于旅册”中按需重看。
- 通过扉页后，首次新建页只保留 `A Book Made For Your Trip`、`旅册`、slogan `为下一次旅行，做一本自己的书。` 和表单；回访用户则直接进入书架。

## 一期生成模型（已确认）

### 一本书的边界

- **自由输入 1–3 个目的地，一次出行一本书。** 不建立城市、行政区或景区的强制层级；`九寨沟`、`成都`、`三星堆`可以被并列输入并生成同一本旅行书。
- 目的地标签只表达用户这趟旅行想去哪里，不要求用户说明兴趣方向；风土人情、建筑、美食、历史、自然与日常生活均由产品主动研究和编排。
- 一期不做地点库、经典路线或用户上传行程；后续是否添加，取决于自由输入的真实使用反馈。

### 创建流程

1. **输入行程** — 首屏问题保持为：`输入目的地后按回车，例如：大理`。
   - 用户自由添加 1–3 个目的地标签，顺序即为本次旅行的线索顺序。
2. **生成** — 生成前展示一句简短承诺；生成后得到标题、副标题、书脊、封面、目录与现场探索线索。

### 生成结果示例

输入：`九寨沟` + `成都` + `三星堆`

- 书名：`慢慢成都`
- 副标题：`三星堆 · 人民公园 · 玉林路`
- 书脊：`慢慢成都`
- 封面：成都的街巷与日常意象为主体；不使用单一景点照片拼贴。

这四项必须同时由生成链路产出，书架不再把“第一个地点的封面”当作整本书封面。

### 后续：一本书可持续修订（已记录，非一期范围）

- 一本旅行书完成后，用户仍可补充新的在意点、补去的地点、照片或笔记，也可以要求删除某段内容或地点；这些不是重新创建一本书，而是对同一趟旅行的编辑请求。
- 系统把这类请求作为一次新的“修订生成”：保留原书和可阅读的旧版本，生成新的 `BookVersion`；用户可在版本记录中查看变化并选择当前公开/阅读版本。
- 用户输入的是意图，而不是直接修改模型产物。例如：“补充当地人的日常”“把三星堆这一节删掉”“把这张照片放入第二章”。编辑器需要先给出将修改哪些章节的预览，再执行。
- 一期不实现自由编辑器、逐段 diff 或版本回退 UI；但数据模型必须预留 `Book → BookVersion → GenerationRun`，避免未来将“补充”误做成另一册重复的书。

## 产品情绪

一本会呼吸的旅行笔记本：纸、印章、路线、手写批注。不是 App，是"物件"。

情绪目标：拿到书的瞬间有"这是为我做的"的专属感；阅读时像在读杂志专题；做任务时像玩寻宝游戏，不像写作业；成册时有仪式感，想晒。

## 视觉词汇

- 纸：米白/暖白纸面、细纹理、书脊阴影、页边打孔或缝线暗示
- 印章：任务完成 = 盖章（圆形印章盖上去的动效），呼应盖章文化
- 路线：目的地之间、章节之间用虚线路线连接
- 手写体：仅用于批注、任务完成签名、封面题名（Caveat/Kalam）
- 地图感：简单 SVG 等高线/方位标，不追求地理精度，是装饰性"勘探图"

## 字体

- 标题：Noto Serif SC 900（已有子集）
- 正文：Noto Sans SC 400/500
- 手写层：Kalam / Caveat（英文小标签、批注）
- 新增字符后必须重跑 `scripts/build-font-subsets.py`

## 色彩角色

- 纸底：`#f7f2e9` 系暖白
- 墨：`#2a2620` 近黑褐
- 印章红：`#b64036`（完成态、关键强调，克制使用）
- 长白蓝绿：`#3d6b6e`（长白山章节主题色，湖水）
- 延吉暖橙：`#b5763a`（延吉章节主题色，米酒/秋色）
- 禁用：紫蓝渐变、发光、毛玻璃

## 布局与间距

- 书页是唯一的容器隐喻：居中单栏，max-width 约 720px，页面像一页页纸
- 桌面端：书页居中，背景是"桌面"（深一级的暖灰，可隐约看到路线纹理）
- 移动端：书页撑满，翻页感用 scroll-snap 或简单页切
- 一页一个主导想法：讲解页不堆任务，任务页不堆讲解

## 动效原则

- 翻页：横向或纵深（scale+位移），不做花哨 3D
- 盖章：任务完成时印章"砸"下来（scale from 1.4→1，轻微旋转），这是全站最重要的动效
- 生成过程：逐行打出"检索进度"，像打字机，1.5–2 秒，不装长
- hover 只用于抬升和墨迹加深

## 组件语气

- 文案：杂志专题式、具体、有细节，不说教
- 任务措辞：用"去找""盯一眼""拍下来""尝一口"，禁用"作业""填空""学习"
- 英文小标签做质感：`FIELD NOTES` `STAMP HERE` `CHAPTER 01` `MADE FOR YOU`
- 每个来源标注真实可点的延伸链接（B站/百科/纪录片）

## 反模式（禁做）

- 通用 SaaS 卡片网格、仪表盘感
- 把书做成"文章列表"——书必须有封面、章节、页
- 大而空的 hero 插画
- 蓝色按钮默认样式
- 任务页出现"作业""打卡签到"字样
- 解释产品本身的 UI 内文案（除一处 Demo 标注）

## v5 追加：固定页高 + 孤独星球式排印

- **书页高度固定**：桌面所有书页同一高度（约 780px 或 82vh 取小），内容超出时页内滚动（带顶部/底部渐隐暗示），翻页时页面不再忽长忽短——书必须有固定的"开本"。移动端书页 = 视口高减去翻页栏，同样页内滚动。
- **孤独星球（guidebook）式排印方向**（借鉴体裁，不抄品牌）：
  - 每个目的地在章节前加一页"目的地开篇页"：超大衬线地名、region 小字、coverLine、一行"速写"事实（如 建议天数 / 最佳季节 / 一句话理由）
  - 章节页头强化：大章号（Fraunces 900 数字）+ tag + 标题的排版块，动态生成的书没有插画时这个块头就是视觉主体
  - 封面更"指南书"：书名、目的地名为主角，edition、 traveller 名字做衬
- 动态生成的书（无插画）与精编样例书（有版画）共存：无图章节用排印块头，有图章节用图，结构天然兼容

## v6 核心内容宪章：【人文旅行文脉八面体】与真实问答法（2026-09）

### 1. 文脉渊源：中国两千年正统《方志学》体例

《旅册》拒绝浮躁庸俗的打卡避坑清单，也坚决反对文人自嗨式的辞藻堆砌。它的内容基石继承自中国两千年正统《方志学》（宋元至明清府志、县志）的严谨八卷体例：
- **舆地（地质自然）**：山川形胜、亿万年地壳雕琢、潮汐候鸟、洋流气候。
- **沿革（历史起源）**：建置兴衰、地名演变、史诗神话、帝国经略。
- **封爵/人物（名人行纪）**：帝王将相、迁客骚人、文博先贤的真实行迹。
- **城池/营造（乡土空间）**：依山傍海的聚落形态、老石墙、海草房、古避风坞。
- **风俗/坛庙（信仰民俗）**：岁时节令、祈海敬神、民间禁忌与民俗生活。
- **物产/食货（风物饮食）**：食材身世、风土风味科学、民间饮食源流。
- **艺文（诗赋意境）**：历代名家题刻散文、方言野趣与诗文意象。
- **市集（市井烟火）**：清晨渔市、老街手艺、当下的市井呼吸与真实生活。


这是古人几千年摸索出来描摹一块土地最完整、不遗漏的骨架。全书章节与多路检索必须源于八面体，杜绝碎片与空泛。

### 2. 问答文风宪章：“有生活真相、有风味科学、有历史来历、不装逼”

全书坚持**好奇心驱动的现场问答**（旅行者的笨问题）：
- **严禁文人装逼腔**：禁止余秋雨式抒情自嗨、禁止“天地浩渺人如蜉蝣”类廉价虚无感悟。
- **严禁弱智弱幼化**：提问必须切中现场旅行者眼见之物的真实好奇（“这啥？”、“为什么有这个现象？”、“是谁发明的？”、“为什么好吃？”）。
- **回答要有硬核说服力**：
  - **有生活真相**：还原真实的市井现场与人情往来；
  - **有风味科学**：讲透物理、化学、生物与地缘机理（氨基酸鲜味协同、乳化反应、海蚀地貌水动力）；
  - **有历史来历**：交代清晰的人名、年代、民间创制源流与演变。

#### 黄金标准范例：

- **范例 A（风味科学与市井身世）**：
  - **问**：海肠捞饭到底是谁发明的？为什么能这么好吃？
  - **解**：不是古代宫廷菜，而是90年代末烟台威海街头大排档食客的“隐藏吃法”。传统鲁菜只有“韭菜炒海肠”，食客舍不得鲜浓的盘底汁，扣上热米饭拌着吃，被福山菜师傅标准化成招牌。海肠富含极高浓度鲜味游离氨基酸（古时福山大厨拿它磨粉当味精），韭菜的挥发性硫化物在高温宽油中与氨基酸发生鲜味协同暴增；海肠开水烫2秒、下锅爆炒15秒锁住脆嫩爆汁，裹上琉璃薄芡拌饭，造就不可替代的味觉暴击。
- **范例 B（食材特性与物理逆袭）**：
  - **问**：来烟台吃海鲜，当地人为什么非得把鲅鱼包成大水饺？
  - **解**：每年春季从冷水洄游而来的春鲅蓄满脂肪，但远洋洄游鱼肉质紧实，整条清蒸必柴。胶东人发现它只有一根主脊骨、全身绝无肌间乱刺；厨师刮出雪白纯鱼肉，按顺时针持续“打水”打入50%高汤，再加入纯猪板油高速搅打——鱼肉蛋白与油脂彻底乳化，变成了如慕斯、豆腐脑般嫩滑的鱼茸，拌入头茬韭菜。薄皮出锅，咬开是一汪滚烫鲜美如酪的鱼汤，把原本粗硬的肉质逆天改造成了极致滑嫩。
- **范例 C（乡土营造与生态智慧）**：
  - **问**：胶东海边老房子的屋顶上那层厚厚的毛茸茸草顶，是长毛发霉了吗？
  - **解**：那是胶东独有的“海草房”，中国北方生态民居的活化石。渔民潜入深海捞取野生鳗草，晒干苫在由海礁石砌成的厚墙上。鳗草富含胶质与盐分，不仅绝不霉烂生虫，更能抗百年台风海雾，夏阻骄阳冬锁严寒，是沿海老祖宗顺应山海的极致营造智慧。
