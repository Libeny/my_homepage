# 《旅册》分阶段生成流水线 v2（主 agent 驱动）

> 本文档是与用户对齐后的**定稿方案**。v1 契约见 PIPELINE.md（当前线上行为），本方案落地后取代其"管线步骤"一节。

## 三条总原则

1. **主 agent 当制片人**：流程推进由主 agent 自主完成（不是代码编排，也不是人点"继续"）。它按 SOP 工作守则派活、收活、验收。
2. **产出落盘为准，记忆不作数**：每阶段产出写 `.context/jobs/<jobId>/stage-N.json`；任何 agent 中途死掉，重开实例读盘从断点继续。
3. **运动员不兼裁判**：阶段准出以机器校验为准（JSON 合法、事实对账、文件存在），排版由 layout-review 独立走查；产出者自评无效。

## 调度方式：主服务唤起 + 文件契约

服务端（serve.py）**不感知 herdr、不感知有几个 agent**，只做三件事：

1. **唤起**：接单后建 job 目录，`subprocess` 启动主 agent（`pi -p "<SOP+任务参数>"`，cwd 设为 job 目录），立即返回 jobId
2. **搬运**：客户端轮询时，把 job 目录里的 `lines.jsonl`（主 agent 选择性披露的进度行）和 `book.json` 转发出去
3. **兜底**：agent 进程已退出但 `book.json` 未出现 → 标记失败、客户端给出重试入口；进程超时不退出 → 看门狗杀掉

主 agent 拿到 SOP 后**全权负责 pipeline 内部**：派几个渠道子 agent、用 herdr 还是直接 subprocess 调 codex/agy，都是它的内部实现细节，对服务端透明。它唯一的义务是遵守文件契约：写 `lines.jsonl`（选择性披露）、落盘各 `stage-N.json`、最终交 `book.json`。

轮询 vs SSE：先保留客户端轮询（已能用，分钟级任务足够）；SSE 实时推送列为后续优化项。

轮询为**增量式**：客户端每次带游标（`GET /api/job?id=xxx&since=N`），服务端只返回第 N 行之后的新进度行 + 当前状态；状态未到 done 就持续轮询。断网重连、App 切后台回来均不丢行、不全量重拉。

## 打卡进展存储（客户端本地优先）

- **书与进展分离**：book.json 生成后不可变；打卡进展（任务勾选、笔记、照片、盖章）是用户在书上的"批注"，按 `bookId + chapterId` 独立命名空间挂载，重新渲染/重新拉书都冲不掉
- **介质**：勾选/笔记/盖章 → localStorage；**照片 blob → IndexedDB**（行中断网可离线拍照，本地可看）
- **云端同步（outbox + 下行拉取）**：每次本地写入同时追加一条事件到 **IndexedDB 事务队列**（对齐 LSE 的 `__transactions` 表；旧 localStorage 队列一次性迁移）；联网 / 每 15s 按序推送 `POST /api/events`，服务端按事件 id **幂等去重**、ack 后才从 IDB 删除，断网则下次续推
- **syncId 全序**（学自 Linear Sync Engine）：服务端给每条事件发全局单调递增整数（计数器落盘 `_counter.json`），取代时间戳当游标；老事件按 serverTs 顺序一次性回填编号
- **下行拉取**：客户端每 15s（及联网恢复时）拉 `GET /api/events?bookId=&since=<syncId>`，把**其他设备**的打卡事件（勾选/笔记/盖章）应用到本地状态并刷新当前页；游标按 bookId 存 localStorage；自己设备的事件跳过；应用是幂等 set 语义
- **归属标识**：本期无账号体系，用 `bookId + 设备 id` 标识归属，服务端先做"事件收件箱"原文留存；账号体系上线后再绑定
- 目标：行中无网照常打卡，数据不丢；有网静默双向同步，多设备一致，用户无感知

## 阶段表（含执行者分工）

| 阶段 | 干什么 | 执行者 | 准出 |
|---|---|---|---|
| S0 接单 | 建 job 目录、subprocess 唤起主 agent | 服务端 | jobId 立即返回 |
| S1 检索 | 主 agent **并行派遣多个渠道子 agent**（herdr 各开 pane），每个渠道一个：① 纪录片（央视网片库 + B站纪录片官方）② 官方网站（景区/文旅局/博物馆官网）③ B站高收藏（搜索 API `order=stow`，标题/简介/字幕）④ 百科词条兜底。各自交**渠道报告**（命中内容 + 事实清单带出处 + 原文摘录；渠道失败如实记"未命中"，不硬凑） | **渠道子 agent × N**（codex，公式化检索无创作） | 每目的地 ≥2 渠道实质命中；URL 全可达；各渠道报告落盘 |
| S2 选题材料 | 主 agent 汇总各渠道报告 → 整理成**选题材料**（事实清单、可挖掘的角度、素材亮点）。只整理，不命题 | **主 agent（主编人格）** | 每条事实能回溯到渠道报告出处 |
| S3 出题 + 写稿 | agy 基于选题材料一口气产出：**书名 + 标题 + 目录 + 大纲 → 逐章写稿 + 现场任务（3 个，动词开头）+ 每章配图 prompt**。章节数不预设，结构从材料里长出来 | **agy**（gemini，品味+文风担当） | JSON 合法；每章立意对账到选题材料；硬事实（年代/数字/地名）逐条对上渠道报告；无"XX概况"式百科腔标题；无占位符 |
| S4 配图 | 按 S3 的配图 prompt 逐章生图。**全书统一视觉语言**：风格 prompt 前缀锁死（木刻版画/蚀刻风、两色套印，与纸质书皮设计语言一致），每章 prompt 只写画面内容；**封面单独伺候**（书名+目的地元素的藏书票式，分享第一眼） | **agy（imagen）**；额度尽则 **LibTV Seedream 5.0 Lite**（联网+中式审美，`libtv image`）兜底，用户无感知 | 文件存在、可解码、尺寸达标；风格前缀校验一致 |
| S5 分页 + 走查 | 分页渲染成书 + 排版走查（0 溢出、图版同页、目录页码对账）+ 成书事实抽查 | **codex**（分页问题修复）+ **layout-review skill（多轮走查）** | 走查 0 溢出；多轮不过→带问题清单降级交付，不阻塞 |
| S6 交付 | book JSON 合并回客户端 + 收尾进度行 | 服务端 | 客户端可翻开 |

明确**不做**的（至少本期）：kimi 选题确认环节、写稿审美拦截、多轮打回循环。内容质量先靠"选题材料喂得厚 + agy 人味"保证，由用户人工验收。

### 主 agent 人选

- **pi**（@mariozechner/pi-coding-agent，需先 `npm i -g` 安装；herdr 起 pane 承载）
- pi 不可用时的应急：**codex 当主 agent**（SOP 手册不变，换的是司机不是路线）
- agy 当前额度已尽，恢复时间未知；涉及 agy 的格子有 LibTV 兜底链

## 客户端披露（趣味层 / 幕后层分离）

- 用户只看到 4–5 行**趣味阶段**（📡 打听底细 → ✏️ 整理选题 → 🖋 写稿 → 🎨 画插图 → 📖 装订），逐行点亮打勾，最后"完成。翻开你的书 →"
- 进度行**文案由主 agent 写**（基于真实产出，如"挖到央视《三星堆·消失与复活》，3 集"），不是代码模板
- 渠道命中数、重试次数、校验细节**不披露**，只写 job 日志文件；进度区留长按/小图标可展开"工作日志"（调试用 + 排查入口）
- 代码兜底：agent 进程异常退出且未写完成行 → 服务端补一行"装订师傅打了个盹，点此重试"，客户端永不卡死

## 目录约定（新增）

```
.context/jobs/<jobId>/
  ├── lines.jsonl         # 进度行（主 agent 追加，客户端轮询源）
  ├── stage-1/            # 渠道报告（每渠道一份）
  │   ├── documentary.json
  │   ├── official.json
  │   ├── bilibili.json
  │   └── baike.json
  ├── stage-2.json        # 选题材料
  ├── stage-3.json        # 书名 + 目录大纲 + 章节稿（含配图 prompt）
  ├── stage-4.json        # 配图产物清单
  └── book.json           # 最终成书
server/sop.md             # 主 agent 工作守则（流程/准出/进度行写法/herdr 用法）
```
