# 《Agent 跑到一半网页刷新了，然后呢？》第二轮审查意见（review-r2）

本轮审查针对 `article-v2.md` 正文，按 `write-taste` 全部规则进行二次深度扫描。重点核查首轮遗留的空泛副词（往往/完全/直接）、名词化、连接词翻译腔（一旦……便能）、结尾升华腔及段间衔接断层。每条均点名模式、引用原句并给出单句修法；不作改写、不打分。

## 一、空泛副词深度清理（往往 / 完全 / 直接）

### 1. 「往往」充水
- **引用原句 1**（L60）：`一个大型 workspace 往往有几十万个对象，客户端不可能把所有数据都塞进浏览器。`
  - **命中美式**：空泛副词（「往往」为习惯性填充词，弱化技术事实）。
  - **修法**：删去「往往」，改为主谓硬句：「一个大型 workspace 动辄几十万个对象，客户端装不下。」
- **引用原句 2**（L71）：`整个过程往往持续几分钟甚至数小时，中间不断产生新的状态。`
  - **命中美式**：空泛副词（「往往」稀释具体时间跨度）。
  - **修法**：删去「往往」：「整个过程持续几分钟到几小时，中间不断产生新状态。」
- **引用原句 3**（L127）：`五条里若缺了一条，缺的往往就是 LSE 三件套里对应的机制。`
  - **命中美式**：空泛副词（「往往」削弱清单判断力）。
  - **修法**：删去「往往」：「五条里缺了哪一条，对应的就是 LSE 三件套里缺的那一块。」

### 2. 「完全」滥用
- **引用原句 1**（L50）：`断线重连、换设备、打开半年没用的电脑，逻辑完全一致：向服务端请求 lastSyncId 之后的变更。`
  - **命中美式**：空泛副词（「完全」提供零信息增量）。
  - **修法**：删去「逻辑完全一致：」，恢复更具画面感的短句：「断线重连、换设备、打开半年没用的电脑，都是同一句话：向服务端请求 lastSyncId 之后的变更。」
- **引用原句 2**（L111）：`服务端把 seq 106 之后的增量事件直接返回，客户端界面接着推进，Agent 完全不需要重跑。`
  - **命中美式**：空泛副词叠加（句内同时出现「直接」与「完全」）。
  - **修法**：双副词同步清理：「服务端补齐 106 之后的事件，客户端界面接着往前走，Agent 不用重跑。」

### 3. 「直接」滥用
- **引用原句 1**（L73）：`LSE 的三件套几乎可以直接平移：`
  - **命中美式**：空泛副词（「直接」为无事实含义的口癖；保留起限定作用的「几乎」）。
  - **修法**：删去「直接」：「LSE 的三件套几乎可以原样平移到 AI Agent：」
- **引用原句 2**（L122, L125）：
  - `断线或刷新后能直接通过 after=lastSeq 增量补齐，还是只能彻底重跑？`
  - `切换其他设备登录，能否直接看到同一任务的实时进度？`
  - **命中美式**：空泛副词与修饰（连续出现「直接」「彻底」）。
  - **修法**：清洗为利落的动作询问：「断线或刷新后能用 after=lastSeq 增量补齐，还是只能从头重跑？」「换一台设备登录，能否看到同一个任务走到哪一步？」

## 二、名词化与假强动词

- **引用原句 1**（L15）：`与此同时生成一条 Transaction，持久化进 IndexedDB 的队列，随后批量发给服务端。`
  - **命中美式**：动作名词化（把入库动作写成了「持久化进……」）。
  - **修法**：拆回具体动词：「同时把一条 Transaction 写进 IndexedDB 队列，随后批量发往服务端。」
- **引用原句 2**（L32）：`Transaction 记录着修改前的旧值，触发 rollback 把内存状态撤回去。`
  - **命中美式**：动作名词化（「触发 rollback」）。
  - **修法**：动词直接干活：「Transaction 存着修改前的旧值，执行 rollback 把内存撤回去。」
- **引用原句 3**（L52）：`客户端发一条创建 Issue 的 Transaction，服务端执行时可能伴随生成 history、activity 并更新计数器。`
  - **命中美式**：公文式名词化（「伴随生成」）。
  - **修法**：换用开发日常动词：「服务端执行时可能顺手写入 history、activity 并更新计数器。」
- **引用原句 4**（L115）：`Linear 同步的是静态业务实体（Issue、Comment、Project），而 AI Agent 同步的则是完整的动态过程……`
  - **命中美式**：大词名词化（「静态业务实体」「完整的动态过程」）。
  - **修法**：换为平实技术词汇：「Linear 同步的是业务数据（Issue、Comment、Project），AI Agent 还要同步执行过程……」
- **引用原句 5**（L121）：`Agent Run 拥有全局递增的事件序号吗？`
  - **命中美式**：假强动词翻译腔（「拥有」代替「有」）。
  - **修法**：改用朴素动词：「Agent Run 有全局递增的事件序号吗？」

## 三、连接词翻译腔与结尾升华腔

### 1. 连接词翻译腔
- **引用原句 1**（L15）：`与此同时生成一条 Transaction……`
  - **命中美式**：英文 meanwhile 直译 padding。
  - **修法**：改为简练中文「同时」。
- **引用原句 2**（L71）：`如果继续按照短请求模式设计，一旦连接断开，就会陷入无法恢复的僵局。`
  - **命中美式**：连接词翻译腔（「一旦……就……」）伴随假深刻情绪词。
  - **修法**：改为干脆的工程因果：「如果按短请求来设计，连接一断，整个过程就全废了。」
- **引用原句 3**（L129）：`一旦完成了这种解耦，重连恢复、页面防刷、多端协同乃至审计重放，都能在同一套体系下顺理成章地解决。`
  - **命中美式**：连接词翻译腔（「一旦……都能……」）与并列名词堆砌。
  - **修法**：拆除套路虚词，还原朴素逻辑：「把 Agent Run 重构为带序号的状态流，网络重连、页面防刷与多端对账，便只是这套机制自然带出的基本能力。」

### 2. 结尾升华腔与过度承诺
- **引用原句**（L129）：`……都能在同一套体系下顺理成章地解决。`
  - **命中美式**：结尾升华金句 / 圆满收尾套话（「顺理成章地解决」）。
  - **修法**：依硬性禁令去除戏剧化升华，结束在扎实的机制推论上。

## 四、句法层残留二元对立与元话语导读

- **引用原句 1**（L5）：`根源不在网络波动，而在交互设计：我们习惯把长达数分钟的 Agent Run 当成一次普通 HTTP 请求。`
  - **命中美式**：二元对立（「不在……而在……」）+ 冒号揭晓。
  - **修法**：直接陈述症结：「根源在交互设计：我们把耗时几分钟的 Agent Run 粗暴当成了一次普通 HTTP 请求。」
- **引用原句 2**（L27）：`这里的关键在于：乐观更新只改内存……`
  - **命中美式**：元话语导读（"The key point is..."）+ 冒号揭晓。
  - **修法**：删去「这里的关键在于：」，直接进入事实：「乐观更新只改内存，本地数据库（IndexedDB）只写服务端确认过的状态。」
- **引用原句 3**（L34）：`简言之：网络失败走 Retry，服务端拒绝走 Rollback。`
  - **命中美式**：元话语导读标签（「简言之：」）与总结复述。
  - **修法**：删去引导标签，该句作为轻快的小结单句存在，或者删去通过删除测试。
- **引用原句 4**（L52）：`这里需要区分两个概念：Transaction 代表客户端意图……`
  - **命中美式**：元话语导读旁白。
  - **修法**：删除引导句，直接陈述机制对比：「Transaction 代表客户端意图（「我要做什么」），Delta 代表服务端事实（「实际发生了什么」）。」
- **引用原句 5**（L56）：`分工很清晰：服务端定胜负……`
  - **命中美式**：冒号揭晓 / 自我评价。
  - **修法**：删去前缀与冒号，直接说事实：「服务端定胜负，客户端 Rebase 只管在结果出来之前别让界面乱掉。」
- **引用原句 6**（L71）：`Agent Run 绝不是一次普通的 HTTP 请求，而是一条持续演进的状态流……`
  - **命中美式**：二元对立（「绝不是……而是……」）。
  - **修法**：直接给出属性判断：「Agent Run 是一条持续演进的状态流……」
- **引用原句 7**（L86）：`具体到接口设计上，不要只提供一个 POST /agent/run 挂着 SSE 长连接干等，而是拆为两步。`
  - **命中美式**：二元对立套路（「不要……而是……」）。
  - **修法**：直接说工程建议：「接口设计上拆成两步，别挂着一个 `POST /agent/run` 的 SSE 长连接干等。」
- **引用原句 8**（L113）：`系统的可靠性不再依赖物理连接是否存活，而是依托于事件流、递增序号、本地状态与可重放机制。`
  - **命中美式**：二元对立（「不再依赖……而是依托于……」）。
  - **修法**：改为正向陈述机制：「系统的可靠性立在四样东西上：事件流、递增序号、本地状态与重放机制。」

## 五、段落承接与语流

- **引用原句**（L13-15）：
  `用户在界面上点一下，不应该等网络返回。`
  `把 Issue 负责人改成 Bob，内存里的模型立即更新……`
  - **命中美式**：段落承接跳跃（前句讲抽象原则，后句无衔接突然出现 Bob）。
  - **修法**：补入承接字眼：「用户在界面上点一下，不应该等网络返回。比如把 Issue 负责人改成 Bob，内存里的模型立即变……」
