## 四、句法层 AI 腔模式库逐条扫描

### A. 句式套路

1. **二元对立（「不是 X，而是 Y」/「不在 X，在 Y」）**
   - **引用原句 1**（L5）：`这个 bug 的根源不在网络，在设计：我们把 Agent Run 当成了一次 HTTP 请求。`
     - **命中美式**：二元对立 + 冒号揭晓。
     - **修法**：直接陈述原因：「根源在于我们把长时间运行的 Agent 粗暴当成了一次普通 HTTP 请求。」
   - **引用原句 2**（L27）：`注意一个细节：乐观更新的是内存，不是本地数据库。本地数据库只写服务端确认过的状态。`
     - **命中美式**：二元对立 + 空泛引导语。
     - **修法**：删去引导词与对立句，写出事实：「LSE 仅在内存里做乐观更新，本地数据库只记录服务端确认过的状态。」
   - **引用原句 3**（L53）：`客户端以 Delta 为准，不以自己的请求为准。`
     - **命中美式**：二元对立尾缀。
     - **修法**：直接陈述规则：「客户端最终只以服务端返回的 Delta 为准更新状态。」
   - **引用原句 4**（L115）：`你需要的不只是一个 Sync Engine，是一个 Agent Sync Engine。`
     - **命中美式**：二元对立升华口号。
     - **修法**：整句删除。

2. **修辞性设问与自问自答对**
   - **引用原句 1**（L13-15）：`第一个问题：用户点了一下，要不要等网络？Linear 的回答是不要。`
     - **命中美式**：修辞性设问 / 自问自答对。
     - **修法**：删去设问与拟人回答，直接给出规则：「用户在界面操作时，无需等待网络返回。」
   - **引用原句 2**（L41）：`第二个问题：多端同时在线，客户端怎么知道自己缺了哪些数据？`
     - **命中美式**：修辞性设问。
     - **修法**：改为平实命题陈述：「多端同时在线时，客户端必须能判断自己遗漏了哪些变更。」
   - **引用原句 3**（L73）：`回到开头的场景。Agent Run 是一次请求吗？不是。`
     - **命中美式**：自问自答对。
     - **修法**：删去问答，直接给出核心属性：「回到开头的场景，Agent Run 绝不是单次短请求，而是一条持续演进的状态流。」

3. **冒号揭晓（将冒号作为揭晓谜底或引导工具）**
   - **引用原句 1**（L3）：`做 AI 应用的人对这个场景不陌生：Agent 跑了八分钟……`
     - **命中美式**：冒号揭晓。
     - **修法**：改为平实叙述：「做 AI 应用的人大多经历过这个场景：Agent 跑了八分钟……」或直接去掉冒号合句。
   - **引用原句 2**（L27）：`注意一个细节：乐观更新的是内存……`
     - **命中美式**：冒号揭晓。
     - **修法**：去掉「注意一个细节：」，直接叙述技术事实。
   - **引用原句 3**（L37）：`LSE 的做法是 Rebase：把你那条"从 Tom 改成 Bob"的 Transaction……`
     - **命中美式**：冒号揭晓。
     - **修法**：将冒号转为谓语动词：「LSE 借助 Rebase 机制，把原先『从 Tom 改成 Bob』的 Transaction……」
   - **引用原句 4**（L69）：`一句话区分：Sync Engine 管"哪些数据要保持一致"，Lazy Loading 管"哪些数据现在值得加载"。`
     - **命中美式**：冒号揭晓 / 元话语总结。
     - **修法**：删去「一句话区分：」，写成完整陈述句：「Sync Engine 负责保证数据一致，Lazy Loading 则决定哪些数据当下值得加载。」

4. **机器人节奏（章节开头结构雷同）**
   - **引用原句**（L13, L41, L61）：
     - `第一个问题：用户点了一下，要不要等网络？`
     - `第二个问题：多端同时在线，客户端怎么知道自己缺了哪些数据？`
     - `第三个问题：一个 workspace 几十万对象，客户端装不下。`
   - **命中美式**：机器人节奏（连续同形序号排比开篇）。
   - **修法**：打破刻板模式。第一节从「界面乐观更新」切入，第二节从「增量对账」切入，第三节直接陈述「数据量过大时的按需策略」。

5. **伪深刻结尾与过度承诺**
   - **引用原句**（L129）：`把 Agent Run 从"长连接请求"改写成"可同步、可恢复、可回放的状态流"，重连、刷新、多端、回放、审计，全都变成顺带的。`
   - **命中美式**：伪深刻结尾 / 戏剧化夸张（「全都变成顺带的」）。
   - **修法**：去除戏剧化夸张，收束在务实工程结论上：「把 Agent Run 重构为可同步的状态流后，断网重连、刷新恢复与多端协同便能在同一套架构下自然闭环。」
