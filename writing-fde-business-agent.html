FDE 焚诀：如何围绕业务打造真正能干活的 Agent

为什么很多团队捏出来的 Agent 用两周就吃灰？真不在模型不够聪明，而是我们总习惯把旧流程里的零散步骤、单次会话里的规矩留给一个“失明又被动”的聊天框。

木鱼拓哉 · 改编整理 改编自 Lauren Tan（@poteto）《Automate Anything with Claude Code》
写在最前 · 为什么把这篇文章放进 FDE 实战体系

去年一年，我在一线帮不同业务搭 Agent。见过太多刚上线很新鲜的“业务助手”，不到两周就又回到人手搬表格、人手催进度。最近读到 Lauren Tan（@poteto）这篇长文，和我踩过的坑完全对得上号：Agent 真能把活接过去，要过四道关——先把终局目标（Goal）拍实，再把老手脑子里的经验蒸馏成 Skill，接着打通真实系统的环境可达，最后挂上自动触发和周度自迭代。原文 5 段压箱底的提示词我都保留了。

SECTION 00 · THE FAILURE MODE

先讲清楚：为什么那么多团队的 Agent，总在两周后吃灰

回头复盘吃灰的 Bot，问题从来不是“模型笨”。更多时候，是我们教它的方法本身就很别扭。

第一，习惯把“今天手工点哪几下”当成需求派给它——“每天帮我抄一遍汇总表格”“发一条日报到群里”，完全没告诉它这些动作到底服务哪项业务结果。

第二，所有规矩都堆在当前聊天框。换天新开一个窗口，昨天踩坑对齐的十几条例外判断全丢，明天还得从头教一遍。

第三，也是最致命的一条：它既看不见现场，也写不回现场。数据要靠人截完图、导完 Excel 贴进去；干完活也只在聊天框里报喜，真要落到数据库、工单状态或渠道群里，还是得人再跑一趟。

FDE 业务落地底层公式
能干活的业务 Agent ＝ 明确的 Goal（终局目标） × [ Skill（蒸馏经验）＋ 自动化（触发执行）＋ 环境可达（拿信息与落操作）]
01 · Goal 定方向 让 Agent 清楚自己对哪项业务结果负责，不只执行零散步骤。
02 · Skill 存经验 把老手习惯写成独立规范文件，换个会话就能直接加载复用。
03 · 环境可达建设 能读到真实业务系统里的关键信息，也能把产出与操作准确落回对应位置。
04 · 自动化与自我迭代 靠事件与定时器自己启动；跑完一周，盯着真实反馈自己改 Skill。
SECTION 01 · GOAL OVER PROCESS

一、1.1 先分清「Goal」和「Process」：把终局结果交给 Agent

@poteto 开篇打了两个贴切的比方：烤出一个苹果派是 Goal，去超市买苹果、削皮、揉面是流程；换好备胎让车继续开是 Goal，支千斤顶、拧螺丝是流程。

把过程里的某一步交给 Agent，它只会像旧式脚本一样照着做——前一步稍微变个字段就卡死，也不知道找替代路径。只有把终局目标交出去，把既有流程只当参考线，它才会反过来挑出“这一步其实不用人点、那张表可以直接删”。

FIELD COMPARISON · 只派旧动作 vs 交出终局 Goal
典型业务场景 只派流程步骤（最容易吃灰） 交出终局 Goal（Agent 开始自己干活）
日常经营监控 “每天帮我把各系统报表搬进汇总表格。” “早 9 点前让团队看清昨天哪项指标异常、该谁跟进。”
Agent 会自己去挑异常单号和原因，不用人先搬整张大表。
销售线索跟进 “自动给每个新询盘回一封模板欢迎邮件。” “提高有效商机转化率，不漏跟高意向客户。”
它会先去 CRM 查这人是否已成交、该归哪个销售，再去推跟进。
研发项目推进 “每周五照例帮我写一份项目周报。” “让项目卡点在恶化前被相关负责人看见并认领。”
常规进度静默落库，真卡了直接到对应任务下 @ 负责人。

1.2 写不清终局 Goal 怎么办？直接让 Agent 像记者一样采访你

落地最卡的往往不是写提示词，而是人自己心里只有个模糊念头：“帮我管管店里的售后”“帮我盯着点运营异常”。@poteto 给了一个实操起手式：先给 Agent 起个代号（下面沿用原文的 Potato），让它反过来采访你。

原文保留提示词 01 · 已有清晰 Goal 的起手式

“嗨 Potato，这是我想让你负责的 Goal：<写下你的目标>。根据这个目标，给你自己挑一个名字和头像吧。”

原文保留提示词 02 · 自己还没想清楚，让 Agent 反采访你

“嗨 Potato，我想让你负责一个目标，但我不太确定怎么描述最合适。你能先向我提些问题、像采访我一样聊聊，直到我们一起确定一个让我满意的 Goal 吗？”

业务检验一问：写完一条 Goal，用一句话校验——“做完之后，业务多了什么收入、省了多少人手，还是挡住了什么风险？”如果只能答出“省得我自己点五下表格”，就还是在写旧动作，需要再往上追问一层。
SECTION 02 · EXPERIENCE DISTILLATION

二、内容与经验蒸馏：别打字教 AI，把隐性判断攒成 Skill

定了 Goal，最忌讳马上打开脚本或让 Agent 开始写工作流。自己动手五分钟就能搞定的活，打字教 AI 半小时还经常教漏。为什么？

因为老手真正在做判断时，脑子里走的是几百个微小的条件反射——打字写 SOP 时，会不自觉把“顺手瞄一眼”“这俩客户不能撞期”这些直觉跳过，恰恰这些被跳过的东西才决定活能不能干对。

2.1 “语音倒脑子 + 强制先复述、不准直接动手”

@poteto 的办法特别朴素：别打字，打开语音输入，像带第一天入职的新同事那样，想到哪说到哪，连续讲五到十分钟。讲的时候重点把这六件事倒干净：

  • 平时顺着哪几个步骤做？眼睛会下意识去盯哪几列关键字段？
  • 手头开了哪些软件、邮箱和业务系统？分别用来查什么？
  • 哪些外部反馈最真实（用户吐槽、退款原因、客服评价），你从哪找？
  • 最怕踩进哪些坑，出现什么苗头时得先停下来核对？
  • 事情做完了，到底算“彻底交付”（落库、发确认、留凭证）的标准是什么？

说完之后，让 Agent 把这段口语整理干净，但立刻按住它，只准它用最直白的大白话复述一遍，不准马上写代码。

原文保留提示词 03 · 语音倒脑子后，强制先复述不准直接动手

“Potato，为了达成这个 Goal，我平时通常是这样做的：<直接语音口述你的真实流程>。我想让你仔细想想如何完全从我手里接管这件事。在正式开始干活之前，请先用简单直白的话，把你理解的我的目标和流程复述一遍，方便我给你反馈和确认。现在先别开始执行，我们先把流程对齐、规划好。”

原文保留提示词 04 · 往返对齐两三轮后，主动砍掉冗余流程

“对照我最开始的那个 Goal，重新审视一下我们刚定好的流程；如果你发现有更好、更高效的做法，随时告诉我。”

2.2 每次只问 1 个问题逼出隐性红线，再写成独立 Skill 文件

原文里有一段特别接地气的细节：给汽修/美容店排预约时，老手心里门清——哪项服务耗时长、哪两个客户排在一块会吵起来、邮件和日历冲突时该信日历还是信客户备注，以及“邮件发出去不算完，写入排班系统且收到客户确认函才算完”。

这些规矩靠自己回忆极难写全，必须逼着 Agent “每次只问一个问题”把你嘴里的条件反射挤出来，然后拿几个真实或极端的反例在对话里考它一次，最后让它把最终定版写成一份独立可复用的 SKILL.md。

原文保留提示词 05 · 单题反问查漏 + 拿真实踩坑反例考它

“Potato，帮我查漏补缺，看看这个流程里我还有哪些东西没告诉你。针对我怎么做决策、去哪里拿信息、怎么检查工作成果，以及什么时候必须找我求助这几个方面向我提问。每次只问一个问题，问完之后再举几个例子带我走一遍，好让我在正式自动化之前先给你反馈。”

SKILL HEADER · 01

明确 Goal 与边界

写死这项技能只对哪项业务结果负责、哪些需求不属于它，免得越帮越乱。

SKILL HEADER · 02

数据源优先级与冲突规则

标明从哪取数、多系统记录打架时信谁（如：系统排班库优先于口头备忘）。

SKILL HEADER · 03

隐性判断与红线

哪些例外可以直接按规则兜底，哪些动作（发版、付款、对外群发）必须停下来喊人批准。

SKILL HEADER · 04

验收标准（DoD）

明确做到哪一步才算彻底交付：既要更新业务表，也要回传确认凭证。

SECTION 03 · ENVIRONMENT REACHABILITY

三、环境可达建设：让它直接拿到真实信息、把操作落回对应位置

有了清晰目标，也有了 SKILL.md，很多业务 Agent 落地还是会卡在最现实的一堵墙前：它碰不到真实的生产环境。

3.1 输入侧：连接器直连 + 自建轻采数工具 + 唯一 ID 串表

如果每天还要靠业务同学截三张图、导一份 CSV 喂给它，那它永远只能当个聊天参谋。真正的环境可达第一步，是把信息输入通道打通：

  • 能直连的直接接：邮箱、IM 平台、数据库、日志、CRM、工单与客户评价后台，只要业务现场在这些工具里流转，就通过受控的连接器（Connector / MCP / API）接给它，让它自己进现场拿一手信息。
  • 现实里没记下来的数据，让它自己建轻工具采回来：@poteto 原文里讲过一个绝佳案例——老板觉得客户等太久，但店里没人记录时间卡在哪一步。他们让 Agent 现场写了一个手机电脑都能点的小页面，店员只干一件事：打四个时间戳（进店、对接顾问、拿到钥匙、修完交付）。两周跑下来，瓶颈究竟卡在接车还是领钥匙一目了然。
  • 跨系统用“唯一 ID”把散落信息拼成闭环：客户邮箱、手机号、订单号（比如 ORD-2048）、工单编号——各系统共用同一把唯一 ID，Agent 就能把外部差评和当天的内部记录自动拼回一起归因。

3.2 输出与操作侧：干完活别只在聊天框汇报，按轻重缓急准确落位

很多人搭 Agent 时只盯着“怎么接数据源”，却忘了另一半同样致命——输出与操作的可达（Action Reachability）。Agent 在角落跑得再卖力，如果最后只能把结果口头甩进聊天框，人还是得手忙脚乱去系统里改状态；反之，要是每扫一条数据就在群里发一条通知，一个刷屏的 Bot 几天内就会被全员静音。

在真实工程落地时，输出和触达必须分级写死到规范里：

  • 常规任务完成 → 直接写回业务对应位置：结果总结、产出链接、状态变更，直接写入对应的任务看板、CRM 字段、数据库记录或工单系统接口；静默落库，不在频道刷“我已扫描第 3 行数据”的废话。
  • 周期性工作汇报 → 按固定节奏推一张结构化简报卡：把一天或一周跑完的几十件小事收拢成一张干净可读的卡片，在约定好的早晚时段推送到指定群或 IM 频道，一眼看到重点和异动。
  • 异常、冲突或不可逆高危动作 → 停在断点，打包选项精确 @ 对的人：一旦遇到两套系统数据打架、或涉及付款/发版/删数据/对外群发这类不可逆节点，立刻停下，把上下文和清晰的 A/B 拍板选项整理好，在对应的沟通流或任务下准确 @ 负责人确认。
SECTION 04 · AUTOMATION & SELF-ITERATION

四、自动化与自我迭代：挂上触发器自动跑，每周盯着反馈改 Skill

4.1 挂上定时或事件触发器，把“人”从触发环里移走

哪怕规矩攒好了，如果每次还得靠人点开输入框发一句话喊它开工，人就依然是整条链路的最大瓶颈。用好两类触发器就够了：

EVENT TRIGGER · 事件醒

有事自己醒

来了新客户邮件、应用商店多了一星差评、新开一条高优工单、代码合入主分支时自动唤醒处理。

SCHEDULE · 定时巡

到点自己巡

每天 07:30 拉全库发早报、每小时巡查一次异常超时单号、每周五下午做周度归档复盘，稳稳在后台运转。

4.2 让系统越跑越好：把“真实反馈”直接喂给它自我迭代

@poteto 在原文后半段提出了一个特别重要的问题：“如果是我自己亲自在做这份活，而且我想越做越好，我会去看什么？”

人靠复盘进步，Agent 系统也是。不要自己手忙脚乱改十遍 prompt，直接把这两类真实反馈源接回给 Agent：外部客诉与结果指标（退单率、差评原因、SLA 超时率）＋ 内部驳回与人工修改记录（人类每次改了它的哪句话、推翻了它的哪个决定）。

设好每周五自动跑一次回溯：让 Agent 统计过去七天“哪类判断被改最多、哪段等待时间莫名拉长”，由它自己起草一版 SKILL.md 修订建议，人只需要点个确认，整条业务流程就完成了一次真实升级。

SECTION 05 · COPY & SEND TO YOUR AGENT

五、准备新搭或救活业务 Agent 前，直接把这 5 个问题发给它

无论你今天准备从零搭一个新业务 Agent，还是手里已经有几个在线上跑但老觉得“不太得劲”的 Bot——别急着写代码或加新工具，先开启一段对话，把下面这 5 个问题按第一人称发给它，先对齐再动手：

用第一人称直接发给你的 Agent · 先对齐再动手

1

目标对不对

“我们当前的需求和目标清不清晰？结合你已经在跑或将要接手的这件事，你理解的终局 Goal 是什么？哪些只是可以砍掉的中间动作？请先用一句话复述你要交付的结果。”

2

经验与红线齐不齐

“你还需要知道哪些我平时的隐性判断、多系统冲突听哪个权威源、以及哪些高危红线必须停下来问我？请每次只问我一个问题，对齐后帮我沉淀成一份 SKILL.md。”

3

环境可达够不够

“你现在能直接拿到完成这件事所需的全部关键信息（IM 系统平台、数据库、日志、工单等）吗？缺不缺唯一 ID 串联或轻采集工具？做完之后你能把产出和操作准确写回对应位置吗？”

4

触达分级准不准

“常规任务完成后怎么静默落库不刷屏？周期汇总往哪发卡片？真遇到异常、数据源打架或高危拍板节点时，你清楚停在哪一步、打包什么 A/B 选项喊我确认吗？”

5

自动触发与自我迭代有没有闭环

“这件事可以挂在哪些事件或定时触发器上自动跑，不用每次等我手动催？跑完一周后，你打算盯哪份真实业务反馈或我的驳回记录，来主动提出下一轮的 SKILL.md 修订建议？”

准备打造/救活一个业务 Agent 前，请你先对照这 5 个问题向我确认（先别急着动手改逻辑，对齐后每次只问我 1 个具体问题）：

1. 【目标对不对】我们当前的需求和目标清不清晰？结合你已经在跑或将要接手的这件事，你理解的终局 Goal 是什么？哪些只是可以砍掉的中间动作？请先用一句话复述你要交付的结果。
2. 【经验与红线齐不齐】你还需要知道哪些我平时的隐性判断、多系统冲突听哪个权威源、以及哪些高危红线必须停下来问我？对齐后请帮我沉淀成一份独立可复用的 SKILL.md。
3. 【环境可达够不够】你现在能直接拿到完成这件事所需的全部关键信息（IM 系统平台、数据库、日志、工单等）吗？缺不缺唯一 ID 串联或轻采集工具？做完之后你能把产出和操作准确写回对应位置吗？
4. 【触达分级准不准】常规任务完成后怎么静默落库不刷屏？周期汇总往哪发卡片？真遇到异常、数据源打架或高危拍板节点时，你清楚停在哪一步、打包什么 A/B 选项喊我确认吗？
5. 【自动触发与自我迭代】这件事可以挂在哪些事件或定时触发器上自动跑，不用每次等我手动催？跑完一周后，你打算盯哪份真实业务反馈或我的驳回记录，来主动提出下一轮的 SKILL.md 修订建议？
