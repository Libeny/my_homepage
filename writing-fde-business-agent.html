FDE 焚诀：如何围绕业务打造真正能干活的 Agent

很多团队搭出的 Bot 用两周就吃灰。多数时候，人只派了旧流程里的零散步骤，老手习惯留在了聊天记录里，系统数据和回写入口也没接通。这套做法围绕 Goal、Skill、环境可触达和自动化四件事展开，让业务 Agent 真正接手日常工作。

木鱼拓哉 参考 Lauren Tan（@poteto）《Automate Anything with Grok Bot》 阅读约 8 分钟
SECTION 01 · THE CORE FORMULA

一、底层公式：为什么多数 Bot 用两周就吃灰？

很多团队花一下午捏出一个 Bot，前两天很新鲜，两周后又回到人手搬表格、催进度。Bot 吃灰，通常是因为它缺了这四个基础条件中的几块：

AGENT ARCHITECTURE EQUATION
能落地的业务 Agent ＝ 明确的 Goal（终局目标）
× [ Skill（蒸馏经验） + 自动化（触发执行） + 环境可触达（拿信息与落操作） ]
Goal 定方向让 Agent 知道自己对哪项业务结果负责。
Skill 存经验把老手脑子里的隐性判断写成规范文件，跨会话可直接复用。
环境可触达建设让 Agent 读到真实业务系统的关键信息，并把输出与操作写回对应位置。
自动化去瓶颈靠事件与定时器自己启动，人不用每次手动喊开始。

下面按实际搭建顺序，从最容易第一步就跑偏的 Goal 开始拆。

SECTION 02 · GOAL OVER PROCESS

二、第一步：先定 Goal，别把「旧流程」当目标

@poteto 在原文开头做了一个清楚的区分：目标（Goal）是你最后要的结果，流程（Process）是去往结果的路线。

按这个标准看常见需求：

  • 烤一个苹果派是目标；买苹果、削皮切块、揉面皮、放进烤箱，那是流程。
  • 换上备胎让车继续开是目标；拿工具箱、支千斤顶、拧螺丝、装新胎，那是流程。

放到业务里，大家最常直接把“旧流程里的某一步”原封不动交给了 Agent。

PROCESS VS. GOAL · 业务目标校准对照
常见误区（把流程当目标） 校准后的真实 Goal（终局目标） 校准后 Agent 行为的变化
“每天把各系统报表搬进汇总表格” 早 9 点前让团队看清哪项指标异常、该谁跟进 自动挑出异常单号与原因推到群里，不必让人先去翻整张表格
“给每个新询盘自动回模板欢迎邮件” 提高有效商机转化率，不漏跟高意向客户 先查 CRM 看客户是否已成交、该分给哪个销售，再决定推给谁跟进
“每周五照例写一份项目流水账周报” 让项目卡点在恶化前被相关负责人看见并认领 常规进度静默落库，一旦卡住立刻在原讨论串 @ 对应负责人

如果你心里只想着一个模糊的方向（比如“管理我的店”“帮我盯运营”），不知道怎么一句话写清 Goal，直接用 @poteto 原文里的第一步提问，先给它起个代号（比如 Potato），让它反过来采访你：

原文保留提问 01 & 02 · 目标对齐与反向采访

如果你已经有清晰目标：
“嗨 Potato，这是我想让你负责的 Goal：<目标>。根据这个目标，给你自己挑一个名字和头像吧。”

如果一时描述不清，让它像记者一样采访你：
“嗨 Potato，我想让你负责一个目标，但我不太确定怎么描述最合适。你能先向我提些问题、像采访我一样聊聊，直到我们一起确定一个让我满意的 Goal 吗？”

检验方法：写完一条 Goal，问一句：“做完后，业务多了什么收入、省了多少人手，或提前挡住了什么风险？”如果只能答出“省得我自己点五下表格”，就还是旧动作。
SECTION 03 · EXPERIENCE DISTILLATION

三、第二步：经验蒸馏，把直觉写进 SKILL.md

很多人卡在从零教 AI：“我自己做只要 5 分钟，写提示词却要写半小时，最后它还是会在奇怪的地方出错。”

因为老手干活靠很多下意识判断，打字写提示词时很容易漏掉。要让 Agent 稳定接手，按下面四步对齐最省事。

3.1 打开语音，5 到 10 分钟一口气倒出来

@poteto 最推荐的方法不是打字，而是直接开语音输入：把它当成第一天入职的新同事，零散、跳脱、口语化都没关系，一口气说 5–10 分钟，重点讲透 6 件事：

  1. 平时顺着哪几步做：从拿到需求到收尾的大致顺序。
  2. 你眼神会特别盯紧哪些坑：哪些数字不对、哪些客户脾气急、哪一步最容易漏。
  3. 手头开了哪些软件和系统：邮箱、IM 系统平台、数据库、日志、工单后台、表格或代码库。
  4. 怎么确认这活“彻底做完了”：是发出邮件算完，还是必须写入系统且拿到回执？
  5. 一手信息从哪查：群聊记录、客户邮件、工单系统还是数据库。
  6. 外部真实反馈在哪看：客户评价、差评工单，还是销售同事在群里的吐槽。

3.2 先让它用大白话复述，不准先动手

语音倒完脑子后，先别让 Agent 连工具干活。先发这段提示词，对齐彼此理解：

原文保留提问 03 · 流程复述确认（不准先动手）

“Potato，为了达成这个 Goal，我平时通常是这样做的：<你的口述流程>。
我想让你思考一下如何完全从我手里接管这件事。在动手之前，先用简单直白的话复述一遍你理解的我的目标和流程，方便我给你反馈和确认。现在先别开始执行，我们先把流程对齐规划好。”

像改实习生周报一样校准两三轮后，再发下面这句，看 AI 有没有更省事的做法：

原文保留提问 04 · 反向优化冗余流程

“对照我最开始的那个 Goal，重新审视一下我们刚定的流程；如果你发现有更好、更高效的做法，随时告诉我。”

3.3 反问式采访：逼出你的“隐性判断”与“求助红线”

@poteto 在原文里举了个细节：排预约时，你知道哪项服务特别费时间、哪两个客户不能排在一起、邮件和日历冲突时该听谁的，以及“邮件发出不算完，预约写库且对方收到确认函才算完”。

这些习惯人靠自己回忆想不全，让 Agent 每次只问一个问题来反问你，再拿过去出过岔子的反例考它：

原文保留提问 05 · 单题反问查漏 + 边界举证

“Potato，帮我查漏补缺，看看这个流程里我还有哪些事没告诉你。针对我怎么做决策、去哪里拿信息、怎么检查工作成果、以及什么时候必须找我求助这几方面向我提问。每次只问一个问题，问完再举几个例子带我走一遍，好让我在正式自动化之前给你反馈。”

3.4 把规矩写进 SKILL.md，别留在聊天记录里

前面三步做完后，@poteto 就直接接工具上线了。但在团队环境里，把对齐好的边界留在一个聊天窗口里不够：明天换新会话、换台电脑，或者换人接手，又得重新讲一遍。

直接让 Agent 把这套规则写成结构化的 SKILL.md，固定写清 4 件事：

# <业务 Skill 名称> / SKILL.md
1. Goal（终局责任）：本技能对哪一项业务结果负责，不管什么。
2. 触发与权威数据源：何时启动；去哪取数；多系统金额或时间冲突时听谁的。
3. 隐性规则与高危红线：老手例外判断，以及发版、付款、对外群发等必须停下来让人确认的节点。
4. 验收标准（Definition of Done）：做到哪一步才算完成（如落库、发确认并回传凭证）。

写进 SKILL.md 后，团队和不同机器都能直接加载复用，规则也会跟着业务一起修订。

SECTION 04 · ENVIRONMENT REACHABILITY

四、第三步：环境可触达建设，读得见信息也操作到位置

有了 Goal 和经验规范，Agent 在公司里依然常常干不了重活。卡点通常在环境触达不够：输入侧读不到业务系统的关键信息，输出侧也没法把结果和动作写回原本的位置。

4.1 输入可触达：直连关键业务信息、补齐盲区、用唯一 ID 串表

  • 接上工具连接器（Connectors / MCP）：把邮箱、IM 系统平台、CRM、数据库、日志、工单系统、应用评价与代码库直连给 Agent，让它自己读一手关键信息，不用人截图或导表格喂给它。
  • 缺少的数据，让 Agent 现场写小工具采出来：@poteto 原文讲过一个汽修店案例。老板总觉得客户等太久，但店里没人记录哪一步耗时长。他们让 Agent 现场搭了一个手机、电脑都能点的小页面，只记 4 个时间戳（进店时间、对接服务顾问时间、拿到钥匙时间、开修与完工时间）。两周后，瓶颈卡在接车还是领钥匙就一目了然。
  • 跨系统必须有唯一 ID 串表：客户邮箱、订单号（如 ORD-2048）、工单编号或 Task ID。只要多个系统共用同一把 ID，Agent 就能把外部差评和当天后台记录自动拼到一起归因。

4.2 输出与操作可触达：写回并操作到对应位置，再做分级触达

光在聊天框里回一句“做好了”不够。结果和动作得直接写回业务原本发生的地方，再按轻重分级通知人：

  1. 常规任务完成 → 直接写回并操作到对应系统位置：把产出链接、状态更新、字段变更写回任务看板、CRM 或工单接口，不在群里刷“我已读取第 3 行数据”这类过程消息。
  2. 周期性汇总 → 定时推送到对应频道的简报卡：把一天或一周跑完的几十件小事，在固定早晚时间收拢成一张干净可读的摘要卡发到指定频道。
  3. 异常、冲突与高危红线 → 在原讨论串打包选项直接 @ 对的人：遇到数据源冲突、信息缺失，或涉及发版、付款、对外群发等不可逆动作时停下来，把事实和 A/B 选项打包，在原讨论位置 @ 负责人确认。
SECTION 05 · AUTOMATION & SELF-ITERATION

五、第四步：自动化与自我迭代，把人从瓶颈位置摘出来

很多人的 Bot 始终只停在“工具”，因为每次运行还等着人手动发一句消息。只要人还是触发开关，人就是系统里最大的瓶颈。

5.1 用事件和定时器，替掉人工口令

  • 事件触发（Event-driven）：来了一封新客户邮件、应用商店多了一条一星差评、群里新开一张工单，或者代码合入主分支时自动唤醒。
  • 定时巡检（Routines / Cron）：每天早 07:30 采集简报、每小时巡检异常单号、每周五下午做周度复盘归档。

5.2 接上外部反馈，每周让它自己改一次 SKILL.md

原文后半段，@poteto 提出一个自检问题：“假如是我自己亲自做这份工作，而且想越做越好，我会去看什么指标？”

把这个真实反馈源（客户退单率、差评内容、人类打回修改记录）直接接给 Agent。每周定时让它回溯一次：哪类判断被人类改得最多？哪段等待时长突然拉长？复盘完，让它主动起草一条对 SKILL.md 规则的修订提案，你确认后合入就行。

SECTION 06 · COPY & ASK YOUR AGENT

六、新搭或救活业务 Agent 前，直接把这 5 个问题发给它

准备新搭业务 Agent，或者想救活已经在跑但效果不好的 Bot 时，可以把这 5 个第一人称问题直接复制发给你的 Agent，先和它把边界对齐：

开干前五连问 · 复制粘贴发给你的 Agent

1. 目标对不对：“我们当前的需求和终局目标清不清晰？结合你现在已经在负责（或我想交给你）的这件事，你理解我们真正要达成的业务 Goal 是什么？当前做法里有哪些只是可以砍掉或替换的中间操作步骤？请先用一句话复述你理解的最终结果。”

2. 经验与红线齐不齐：“为了稳定完成这个目标，你还需要知道哪些我平时下意识做的判断标准、数据冲突时听哪个权威系统、以及哪些高危边界必须先停下问我？请每次只问我一个问题，对齐后帮我整理沉淀成一份可复用的 SKILL.md。”

3. 环境可触达够不够：“你现在能拿到完成这件事所需的全部真实环境关键信息（IM 系统平台、数据库、日志、工单等）吗？跨系统之间缺不缺统一 ID 串表、要不要现场写个小工具采集盲区？做完后你能直接输出并操作到对应的系统位置吗？”

4. 触达分级准不准：“常规任务完成后怎么静默写回对应位置而不刷屏？周期性汇总发到哪里？遇到异常或高危拍板节点时，你清楚应该停在哪一步、打包什么选项来喊我确认吗？”

5. 自动化与自迭代通没通：“这件事接下来可以挂在哪些事件触发器或定时 Routine 上自动跑起来，不用每次等我手动喊你？跑完一周后，你准备盯哪份真实反馈或驳回记录来主动提议修订 SKILL.md？”
